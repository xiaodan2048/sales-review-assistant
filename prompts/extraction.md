# 8 项关键信息抽取 Prompt（v2，上线版）

> 根据产品方案里的字段定义整理的示意版本，模型为 DeepSeek-V3。抽取结果只是候选，销售逐条点“对 / 改”后才写进客户档案。

## System

```text
你负责从销售拜访幼儿园的对话转写中，抽取下面 8 项客户信息。
每一项都必须附上原话和时间戳；原话从转写中逐字复制。
对话里没提到的项，输出 null，不要推测。

## 字段
1. decision_chain   拍板人与决策链：谁参与决策、谁最终拍板、谁付款（园长 / 业务园长或保教主任 / 举办者或集团）
2. budget           预算与审批时间：预算多少、什么时候审批
3. current_solution 在用方案：纸质记录、其他园务系统或没有
4. scale            园所规模：班级数、教师数
5. top_pain         最痛的场景：园长或老师说的最具体的一个困难
6. main_concern     主要顾虑：归入 6 类之一——老师负担 / 家长隐私与幼儿影像安全 / 价格与预算 / 已有系统 / 效果担忧 / 决策流程
7. teacher_attitude 老师的态度：全园老师整体的态度
8. next_step        下一步约定：谁、做什么、哪天前

## 容易抽错的地方
- teacher_attitude 只抽园长描述“老师们 / 大家”的整体态度。园长转述某一位老师的个人意见时，不算全园态度，输出 null。
- next_step 必须有明确时间或明确动作。“好的，你先发资料”“我们再考虑考虑”不算约定，输出 null。

只输出 JSON，不要输出其他内容。
```

## 输出格式

```json
{
  "decision_chain":   {"value": "园长初筛，举办者拍板付款", "t": "07:15", "quote": "这个最后还得我们理事长点头"},
  "budget":           {"value": "约两万元，八月底前审批", "t": "18:02", "quote": "这块预算两万左右，八月底前要批下来"},
  "current_solution": {"value": "纸质观察记录本", "t": "02:30", "quote": "现在都是手写在本子上"},
  "scale":            {"value": "9 个班，约 30 名老师", "t": "01:40", "quote": "我们九个班，老师三十个左右"},
  "top_pain":         {"value": "期末集中补写观察记录", "t": "04:05", "quote": "期末那两周老师天天加班补记录"},
  "main_concern":     {"category": "老师负担", "value": "担心多一个系统要填", "t": "11:20", "quote": "别又是一个要老师天天填的东西"},
  "teacher_attitude": null,
  "next_step":        {"who": "销售", "what": "带两个班试用", "due": "下周三前", "t": "24:50", "quote": "那下周三之前先给大班两个班开起来试试"}
}
```

## 输出后的规则校验（代码执行）

- 每项的 `quote` 必须能在转写中找到，找不到就删掉这一项（v2 原始输出 106 条，校验后丢弃 7 条）。
- 抽取结果在页面上默认是“待确认”，销售点“对”才变成“已确认”并写入档案；点“改”可以直接编辑。

## 评测结果（v2）

准确率 91%（90/99），召回率 76%（90/118）。召回最低的是“预算与审批时间”（44%）和“老师的态度”（56%）。详见 [评测集与数据](../docs/评测集与数据.md#信息抽取8-个字段v2)。

## 下一版（v3）计划

预算召回低，一半是因为园长很少直说预算。v3 在“容易抽错的地方”里加入隐含表达示例：

```text
- 预算很少被直接说出来。下面这类隐含说法也算 budget，要抽出来：
  “等开学后跟举办者报一下”“今年的钱已经批完了，明年三月再看”“集团那边每年底统一报”
```

另一半是销售本身没问（20 段里只有 9 段聊到预算），这靠 Prompt 解决不了，所以放到了提醒卡的“这次必拿的 3 件事”里。
